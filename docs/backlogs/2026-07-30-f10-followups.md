## 2. Skill rewrite depth drift [Minor — maintainability]

The three headless skills were rewritten to differing depths: `gh-marketplace-sync-headless` is
driver-first; `gh-plan-sync-headless` still carries the full Phase 1–7 library choreography
(incl. `APPLY_GITHUB`/`APPLY_DOC`/`apply_reconcile` prose) *alongside* the driver Execution
shell; generated redirects phases to `build_result` but keeps multi-phase prose. The enrollment
guard (`headless-driver-map.yaml` + `test_skills_shell_drivers.py`) blocks *unmapped* skills,
not residual dual prose. A future agent could over-read the residual phases. Trim the plan-sync
skill's residual library choreography to match the driver-first shape.

## 3. Config-ABORT strictness drift [Minor — operator UX]

Missing `plan-sync.yaml` / `generated.yaml` → validated ABORT; but a **missing/corrupt
`marketplace-sync.yaml`** → empty bindings + success (`marketplace_sync_run.py` ~230-240), and a
**corrupt `plan-sync.yaml`** load → empty `bindings=[]` + continue (`plan_sync_run.py`
~175-182), not ABORT. An operator sees green zero-scan results for a broken config. Domain-
reasonable for optional marketplace; consider tightening the corrupt-config path to ABORT for
parity with the missing-file path.
